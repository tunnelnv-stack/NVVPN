# NVVPN — адресные лицензионные исправления

Основа: Windows 0.4.2, локальный тестовый выпуск готовится отдельно. Дата проверки: 19 ноября 2026 года. Это технический отчёт, а не разрешение на распространение. Технические исправления не закрывают вопросы Wintun, прав на собственную оболочку и утверждения соглашения.

## Структура исходного комплекта

В `NVVPN-Sources.zip` сохранены `NVVPN/windows-app`, общий `NVVPN/src/Profile.cs`, исходники Go-модулей в `dependencies`, стандартная библиотека в `Go-runtime-source`, исходные module ZIP и метаданные в локальном Go cache. `DEPENDENCIES.json` связывает используемые модули с версиями и хешами. `MODULE-METADATA.json` перечисляет каждый экспортированный `.mod`/`.info` и SHA-256. Экспорт `.mod` ограничен версиями из текущего `go.sum` и фактически использованными модулями; `.info` — только использованными модулями. Для записанных в `go.sum` `.mod` проверяется Go h1. Общий кэш других проектов больше не обходится.

`NVVPN/vendor/license-supplement/PROVENANCE.json` — явный перечень дополнительных материалов с происхождением и SHA-256. Упаковка прекращается при несовпадении любого хеша; новые файлы автоматически в комплект не попадают. Полные GPLv3 и LGPLv3 лежат также в корне исходного ZIP. Прежний краткий notice sing-box сохранён как исходный файл, но больше не выдаётся за полный текст GPL.

Для сборки приложения и движка использовать `SOURCE-README.md` и `rebuild-source.ps1`. Требуются внешние инструменты Windows/.NET/Go; наличие исходников Go runtime не заменяет установленный компилятор Go. Офлайн-восстановление из итогового ZIP должно проверяться после объединения изменений. Эта проверка не доказывает воспроизводимость подписи стороннего драйвера или юридическую готовность.

## Wintun: открытый вопрос и минимальный вариант решения

Wintun 0.14.1 существует и отдельной DLL, и embedded-байтами в `sing-tun/internal/wintun`; фактическая загрузка идёт через `memmod.LoadLibrary(dllContent)`. AMD64 DLL имеет SHA-256 `e5da8447dc2c320edc0fc52fa01885c103de8c118481f683643cacc3220dafce`. Неизменность файла подтверждает происхождение, но сама по себе не подтверждает допустимость способа загрузки и GPL-совместимость.

Сохранена Prebuilt Binaries License. Она отличается от GPLv2 исходников Wintun и MIT Go-обёрток. [Официальная страница Wintun](https://www.wintun.net/) отдельно описывает исходники и распространяемые подписанные DLL. Нельзя автоматически применять к текущей комбинации исключение System Libraries или объявлять её простым агрегатом.

Минимальное решение без изменения работающей сети: получить письменное подтверждение правообладателя Wintun для точного сценария «неизменённая подписанная 0.14.1 DLL embedded в GPLv3-or-later Go executable, загрузка memmod, вызовы Permitted API» и отдельно оценить совместимость с применимыми GPL-обязательствами. До подтверждения считать вопрос открытым.

Если embedded/memmod не допускается, следующий ограниченный технический вариант для отдельного согласования: удалить только embedded-копию, загружать неизменённую подписанную внешнюю DLL из контролируемого абсолютного пути штатным Windows loader, сохранить hash/signature/path checks и существующий TUN API. Сначала изолированные тесты, затем согласованные сетевые тесты. Этот вариант сам по себе также не доказывает GPL-совместимость. В настоящем изменении он НЕ реализован.

Объект находится в распространяемых исходниках модуля; пакет `runsc/sandbox/bpf` не входит в Windows go list -deps, и точные байты объекта отсутствуют в проверенном Windows EXE. Применять к нему GPL только на основании общего предположения об eBPF не требуется. Его пересборка побайтно не выполнялась.
