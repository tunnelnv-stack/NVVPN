# Подготовка выпуска NVVPN

Канал: `tunnelnv-stack/NVVPN`. Контакт проекта: `tunnelnv@gmail.com`.
Ни один сценарий этого комплекта не публикует данные и не создаёт токены.

Версия хранится в `release-version.txt`, изменения — в `release-notes.txt`.
Один commit/tag соответствует одному набору исходников. Сначала собираются и
проверяются все файлы; разрешение владельца на публикацию запрашивается отдельно.

## Сборка и состав

На Windows x64 нужны .NET Framework 4.8, PowerShell, Python 3, Go 1.27.4,
Inno Setup 7.1.1. Полный архив Source содержит точные модули и материалы сборки.
См. `SOURCE-README.md`. `build-installer.ps1 -ReleaseDirectory <новая-папка>`
создаёт Setup, portable, Source и SHA256SUMS. Готовый выпуск не перезаписывать.
Прежние исходники, лицензии и бинарные выпуски сохраняются.

Подписанный манифест создаёт локальная утилита ReleaseTools из исходника
`ReleaseTools.cs`, `Updates.cs`, `src/Profile.cs` (.NET csc, ссылки
System.Web.Extensions.dll и System.Security.dll). Команда:

```text
ReleaseTools.exe sign PRIVATE_DPAPI RELEASE_DIR VERSION COMMIT SEQUENCE NOTES_FILE
```

Здесь PRIVATE_DPAPI — путь к локальному защищённому ключу, не содержимое ключа.
Файл должен быть защищён ACL и DPAPI CurrentUser. Ключ не включается в Git,
артефакты или CI. Утилита подписывает точные UTF-8-байты JSON RSA-3072/SHA-256
(PKCS#1 v1.5), проверяет подпись своим публичным ключом и не перезаписывает манифест.
Установленный клиент доверяет только публичному ключу из UpdateTrust.cs.
Самостоятельная сборка позволяет заменить этот публичный ключ своим; секрет
издателя для компиляции и запуска изменённого клиента не нужен.

Порядок окончательного выпуска: чистый commit → сборка/тесты → точный Source ZIP →
SHA256SUMS → подписанный манифест → проверка всех файлов → согласование → публикация.
Если меняется любой подписанный файл, нужен новый номер и новый комплект.
SEQUENCE должен возрастать, время действия манифеста — 180 суток. Для обновления
истёкших сведений используется новый выпуск; обхода проверки срока нет.

## GitHub после отдельного разрешения

Сначала включить Release immutability в Settings репозитория. Создать draft,
привязанный к точному тегу и commit, загрузить Setup, portable, Source,
SHA256SUMS, release-manifest.json и release-manifest.sig. Проверить состав,
затем опубликовать draft. После включения неизменяемости assets/tag защищаются
при публикации; добавлять недостающий исходный архив позднее нельзя.
Предварительные версии отмечать prerelease; стабильный Latest должен быть именно
актуальным стабильным Windows-выпуском. Неизменяемость дополняет проверку подписи,
не заменяет её. [Официальная документация](https://docs.github.com/en/code-security/how-tos/secure-your-supply-chain/establish-provenance-and-integrity/prevent-release-changes).

Пока GitHub-публикации нет, исходники остаются в обоих пакетах; кнопка GitHub
ссылается на будущую страницу конкретной версии и может возвращать 404.
Кнопка локального архива работает без интернета. Удаление большого архива требует
отдельной проверки доступности исходников и применимого способа распространения.

## Ограничения перед публичным выпуском

Лицензия собственной оболочки и ресурсов требует решения правообладателя.
Остаются вопросы GPL/Wintun (включая embedded/memmod) и применения LGPL к WinDivert.
См. LICENSE-AUDIT.md, LICENSE-REMEDIATION.md. В комплекте сохранены исходники
драйвера WinDivert, лицензионные дополнения Inno и gVisor, тексты лицензий и notices.
Этот локальный проект не выдаётся за юридически разрешённую публичную публикацию.

Первая загрузка с настоящего GitHub, UAC, полный цикл в Program Files и сетевой
сеанс требуют отдельной проверки. Локальные фикстуры и изолированный установщик
не доказывают прохождение этих проверок. При потере ключа подписи нельзя просто
заменить ключ в скачанном JSON: нужен независимо доставленный доверенный клиент.
